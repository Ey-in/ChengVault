14 // Systematic RS(12,10) sidecar implementation
15 // -----------------------------------------
16 // This is erasure coding over byte positions in equally sized shards.
17 // SHA256 first locates a bad shard; RS then reconstructs up to two erasures.
18 // Without location information, two parity shards do not correct two arbitrary
19 // unknown errors. Reporting that distinction is part of the public contract.
20 // Each archive stripe consists of ten 1 MiB data shards and two parity shards.
21 // Padding belongs to shard hashes but not to the whole-archive hash.
22 // Matrix construction uses GF(256) arithmetic modulo polynomial 0x11D.
23 // Field tables are generated locally, and matrix inversion is local code.
24 // No third-party codec or external repair program performs these operations.
25 // The first ten rows of the generator are identity rows, retaining data bytes.
26 // Any ten distinct rows form an invertible matrix under the Vandermonde code.
27 // File recovery never edits the damaged source or its supplied sidecar.
28 // Validated output is published at a new path through QSaveFile.
29 // Temporary files are automatically removed on exceptions or cancellation.
30 // Both metadata copies have their own locator and checksum.
31 // A destroyed front length therefore cannot hide an intact tail copy.
32 // Conflicting valid metadata copies are rejected instead of guessing intent.
33 // Truncated shards are erasures; inserting bytes is not a supported corruption.
34 // The metadata checksum detects accidents, not hostile re-signing by an
35 // attacker who can rewrite both sidecar copies and all unkeyed checksums.
36 // The encrypted archive's own authentication must still pass after repair.
37 // Holding only one stripe keeps memory roughly proportional to 12 MiB.
38 // Index memory grows by 12 hashes per stripe and has an explicit upper bound.
