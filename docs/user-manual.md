# 澄匣备份用户手册

## 1. 启动与第一次备份

解压完整运行包，双击 `ChengVault.exe`。界面左侧依次为“总览”“创建备份”“浏览与恢复”“自动任务”“远程仓库”“检查与修复”“操作日志”“设置与帮助”。底部显示进度和当前步骤，可取消耗时任务。

在“创建备份”中添加文件或目录，每行一个来源。多个来源的根名称应不同。输出位置不能与来源重叠或位于来源内部，避免把备份再次备份进去。

保存方式有两种：

- **单文件归档**：适合交付、拷贝和离线保存，输出一个文件；可选择索引归档或 PAX/TAR，压缩与密码加密可独立选择。
- **增量版本仓库**：选择一个新的空目录；以后继续选择该仓库生成新快照，未变化块直接复用。仓库始终加密。

选择 Huffman、LZ77 或不压缩。加密选择 AES-256 或 ChaCha20 并输入备份密码；它们均包含认证校验。独立归档可以选择不加密。密码不正确或认证失败时不会输出解密明文。

默认严格恢复元数据；如权限不足，可在设置中明确选择允许元数据警告。宽松模式不会忽略文件数据读取或校验失败。

完成设置后先“预览文件”，检查每项是否入选及原因，再点击“开始备份”。索引格式和 PAX/TAR 都是实际完整打包，不是仅生成文件列表。

## 2. 自定义筛选

在“筛选规则…”中配置条件，不填写的条件不起限制作用。排除条件优先；不同类别的条件同时满足才入选。程序保留命中文件需要的祖先目录。

| 条件 | 示例及单位 |
|---|---|
| 路径 | `project/src/*`；排除 `project/build` 及后代 |
| 类型 | `file`、`directory`、`symlink`、`junction`、`hardlink`；扩展名如 `cpp,hpp,txt` |
| 名字 | `*.cpp`、`报告*`；可分别包含和排除 |
| 时间 | 创建、修改或访问时间；ISO 8601 时间区间 |
| 尺寸 | 字节，最小/最大边界均包含 |
| 用户 | Windows 文件属主账户名或 SID；不是网盘登录账户 |
| 属性 | Win32 文件属性位，例如隐藏、只读 |
| 深度 | 所选根目录为 0 |
| 文本包含 | 主数据流中的 UTF-8 文本，不对二进制文件作编码猜测 |
| 相对清单变化 | 先从恢复页导出旧清单 JSON，再选择它作为比较基准 |

变化筛选比较路径、类型、大小、最后修改时间和属性。它不是逐字节比较工具；人为保持原时间与大小的内容修改可能不会被此筛选选中。未开启该筛选时，仓库备份仍逐块计算内容标识，能够检测数据变化。

## 3. 浏览、解包、解压、解密和恢复

进入“浏览与恢复”，选择归档文件或仓库，输入对应备份密码，点击“读取备份”。仓库会列出快照，选择要恢复的版本。可先“完整校验”，再选择需要的文件。

选择一个恢复目录，点击“恢复已勾选文件”。程序自动完成所需的解密、解压和解包，随后建立目录、写入数据与 ADS、建立链接，最后恢复时间及权限。无需用户按不同算法分别手动解码。

默认不覆盖已有文件。允许覆盖时，程序先写临时文件并校验，再替换原文件，不先删除原文件。整个目录不是单一事务；中途失败时，已经成功恢复的文件会保留，日志会指出失败项。

硬链接恢复后仍共享数据；符号链接和 Junction 保留目标。绝对链接可能仍指向原来的位置，不会自动改写为恢复目录内部的路径。稀疏文件保留逻辑长度和空洞，ADS 保留流名称与内容。未知重解析点会明确失败。

符号链接创建需要 Windows 开发者模式或适当权限；设置外部账户的属主、组、权限也可能需要提升权限。权限不足不能视为已成功保留该元数据。

## 4. 定时与实时备份

先在“创建备份”页填写来源、筛选、仓库保存位置和密码，再到“自动任务”设置任务名称及模式。

- 固定间隔使用秒数。
- 每天使用 `HH:mm`。
- 每周选择星期与时间。
- 实时模式感知新增、修改、删除和重命名，合并连续事件后备份。

设置保留版本数，最少为 1；保留天数填 0 表示不按年龄淘汰。点击“创建并启动任务”。后台进程使用当前 Windows 用户 DPAPI 保护的仓库主密钥，不在任务 JSON 中保存密码。

任务建立后，关闭 GUI 不会停止后台进程。可在设置中启动后台进程和配置登录后自动启动；也可在任务列表暂停、启用或删除任务。此功能仅在当前用户登录会话内运行。

文件写入冲突会产生错误并由后台重试。实时文件事件只是触发信号，程序仍重新扫描并建立完整快照。没有数据库跨文件事务或 VSS 保证。

## 5. 网络备份与用户管理

先按 `network.md` 在服务器创建账户和设备授权。服务器默认仅监听 `127.0.0.1:48484`；局域网需显式监听可达地址。

在“远程仓库”填写服务器、端口、账户、登录密码、设备 ID 和 64 位十六进制配对密钥。登录密码用于身份验证，备份密码用于本地仓库解密，两者不可混淆。

选择已存在的本地仓库，点击“上传本地仓库”。第一次上传所有缺失密文对象；以后只上传新块、新清单及变化的配置。重复上传会传送控制消息，但不会重传已有数据块。中断后再次上传可续传已接收的分段。

连接并列出仓库后，选择远程仓库和一个空的本地目录，点击“下载选中仓库”。下载完成后到恢复页输入备份密码恢复。服务器不能从登录密码获得文件明文。

管理员通过“账户与设备管理”创建账户、设置配额、禁用/启用账户、重置登录密码、授权或撤销设备。普通账户在服务端也会被拒绝管理操作，不只是界面隐藏按钮。

## 6. 冗余纠错

创建独立归档时可勾选同时生成 `.cvr`；也可在“检查与修复”中对现有完整归档生成纠错文件。建议把归档和纠错文件放在不同存储位置。

RS(12,10) 每组含 10 个数据分片和 2 个校验分片，分片为 1 MiB。SHA-256 定位损坏后，每组最多恢复两个损坏或缺失分片，数据片和校验片共同计数。它不意味着文件任意位置损坏 20% 都可修复。

“检查损坏”先给出检测结果。“修复到新文件”使用指定归档与对应 `.cvr`，写入一个新的修复文件，成功后校验整包摘要，原文件保持不变。超过修复能力、纠错元数据都损坏、修复文件不匹配时明确失败。加密归档修复后仍需正确密码才能恢复。

## 7. CLI 示例

在运行包目录的 PowerShell 中设置本次进程密码；不要把真实密码写进提交文档或 Git。

```powershell
$env:CHENGVAULT_PASSWORD = '仅用于本地演示的密码'
.\ChengVaultCli.exe backup --source D:\demo\source --output D:\demo\backup.cva --format indexed --compression lz77 --cipher chacha20
.\ChengVaultCli.exe verify --input D:\demo\backup.cva
.\ChengVaultCli.exe restore --input D:\demo\backup.cva --output D:\demo\restored
.\ChengVaultCli.exe repo-backup --source D:\demo\source --repo D:\demo\repository --compression huffman --cipher aes256
.\ChengVaultCli.exe repo-list --repo D:\demo\repository
.\ChengVaultCli.exe repo-restore --repo D:\demo\repository --snapshot '从列表取得的UUID' --output D:\demo\version-restored
.\ChengVaultCli.exe repo-prune --repo D:\demo\repository --keep-count 10 --keep-days 30
.\ChengVaultCli.exe repair-create --input D:\demo\backup.cva --sidecar D:\demo\backup.cvr
.\ChengVaultCli.exe repair-check --input D:\demo\backup.cva --sidecar D:\demo\backup.cvr
.\ChengVaultCli.exe repair-recover --input D:\demo\backup.cva --sidecar D:\demo\backup.cvr --output D:\demo\repaired.cva
```

`--lenient-metadata` 显式允许元数据权限警告；`--overwrite` 显式允许恢复覆盖；`--select` 指定清单中的相对路径；`--plan` 读取计划 JSON。所有命令用退出码表示成功与失败，正常结果为 JSON。

## 8. 排错与数据位置

查看“操作日志”中的结构化错误和后台日志。任务数据位于当前 Windows 用户的应用数据目录，由 `QStandardPaths::AppLocalDataLocation` 决定，通常在 `%LOCALAPPDATA%\ChengVault\ChengVault`；实际位置以程序创建的目录为准。

“仓库忙”表示备份、恢复、上传或淘汰正在使用同一仓库，等待该任务结束再试。“密码错误/认证失败”也可能表示文件被篡改，不能通过忽略校验强行恢复。“文件占用”表示读取时检测到并发写入冲突。“未知重解析点”表示该对象没有在支持的 NTFS 类型内。

发布包的 `checksums.json` 可用于核对运行文件，`runtime-dependencies.csv` 和 `runtime-packages.json` 记录实际依赖。不要只复制四个 EXE 而漏掉 DLL 和 `plugins/platforms/qwindows.dll`。
