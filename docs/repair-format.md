# CVR1 冗余修复文件格式

`.cvr` 是原始归档的独立侧车文件。它处理的是归档完成打包、压缩及加密后的字节，不解析归档内部文件名。生成和修复操作都拒绝覆盖已经存在的目标文件。

## 布局与独立定位

| 顺序 | 长度 | 内容 |
|---|---:|---|
| 1 | 8 | ASCII `CVRHEAD1` |
| 2 | 8 | 元数据 JSON 字节数，大端 u64 |
| 3 | 32 | 元数据 JSON 的 SHA256 |
| 4 | M | UTF-8 紧凑 JSON，第一份 |
| 5 | 分组数 × 2 × 1 MiB | 每组的第 10、11 号校验分片 |
| 6 | M | 完全相同的 JSON，第二份 |
| 7 | 32 | 元数据 JSON 的 SHA256 |
| 8 | 8 | 元数据 JSON 字节数，大端 u64 |
| 9 | 8 | ASCII `CVRTAIL1` |

首部 locator 为前 48 字节，尾部 locator 为最后 48 字节。尾部的元数据长度来自自己的 locator，不依赖损坏的头部字段。因此头部 magic、长度或摘要损坏时仍可从尾部定位有效元数据。

单份 JSON 最大 128 MiB，最多 100000 个分组（约 0.95 TiB 原始数据）。解析时先限制长度，再读取及验证 SHA256，再解析 JSON。有效头尾内容不同必须拒绝；不能任选其一。只有一份有效时允许继续，结果报告使用了冗余索引。

## 元数据字段

```json
{
  "version": 1,
  "shardSize": 1048576,
  "dataShards": 10,
  "parityShards": 2,
  "originalSize": "2097289",
  "archiveSha256": "64 个小写十六进制字符",
  "groups": [
    ["D0 摘要", "D1 摘要", "...", "D9 摘要", "P0 摘要", "P1 摘要"]
  ]
}
```

示例中的摘要占位符仅说明结构，真实文件必须为 64 位小写十六进制。`originalSize` 用十进制字符串保存，避免 JSON double 在大整数上丢失精度。分组数必须等于 `ceil(originalSize / 10 MiB)`，每组恰好 12 个摘要。

SHA256 对每片的完整 1 MiB 计算，包括末组零填充。整包摘要只计算原始长度的字节，不包含填充。空归档具有 0 组，整包摘要为 SHA256(empty)，仍保存两份有效元数据。

## 生成过程

1. 只读打开归档，记录原长度与修改时间。
2. 每次读取最多 10 个 1 MiB 数据片，填零，计算两片 RS 校验；校验片顺序写入自动清理的临时文件。
3. 同时增量计算整包 SHA256，记录每个数据片和校验片的摘要。
4. 读完检查原归档长度和修改时间是否变化；有变化则失败。
5. 使用 `QSaveFile` 写入头 locator、第一份元数据、校验片、第二份元数据和尾 locator。
6. 在提交前再次检查取消状态和目标不存在；原子提交。禁用 `QSaveFile` 直接覆盖回退。

临时校验文件和最终 `.cvr` 在生成期间会同时占用空间，除了归档本体，峰值临时开销约为两份校验区加两份元数据。运行界面应说明空间估算。

## 检查、定位与修复

检查逐片比较摘要，短读视为缺失片，不用错误字节参与解码。原文件尾部截断可以被定位为缺失；中间删除或插入会改变所有后续边界，通常超出本算法能力。比原始长度更长的归档直接拒绝。

同组超过 2 个损坏片立即报告超出能力；不生成成功结果。两个校验片都损坏而数据完好时，可以重建归档，但当前 `recover` 仅输出归档，不自动重写侧车。

修复过程在新的 `QSaveFile` 临时结果中顺序写入重建数据，按原始长度去掉末组填充。每片恢复后再验摘要，最终整包摘要也必须一致。只有所有检查通过、没有取消、目标仍不存在时才提交。错误密码与修复是两回事：修复后的加密归档仍需要正确密码解密。

`check` 返回 JSON：`healthy`、`archiveHealthy`、`recoverable`、`damagedShards`、`damagedGroups`、`headMetadataValid`、`tailMetadataValid`、`originalSize` 和 `archiveSha256`。损坏分组列出 0 起始组号及分片编号，其中 0–9 为数据片，10–11 为校验片。大整数使用十进制字符串。

## 容量与可信边界

- 完整组冗余校验开销为 20%，另有双份索引。最后不足 10 MiB 的组仍写入 2 MiB 校验片，小归档的开销可能远大于 20%。
- 每组只能恢复最多 2 个已定位片。两个不同分组可各自修复 2 片；一个分组损坏 3 片就不能恢复。
- 双份索引处理意外损坏，不提供第三份容灾副本。两份都损坏、缺失或冲突时拒绝修复。
- SHA256 在此提供错误定位；无密钥的修复文件不是防恶意伪造的签名。加密归档自身的 HMAC 必须在后续恢复时验证。
- 目标存在检查和原子提交保护普通误操作；不能抵抗拥有同目录写权限、在检查与提交之间主动竞争的本机攻击者。
