## 真实缺陷及修复

1. **PAX 扩展头填充未校验。** 原实现读取扩展头后的对齐字节但不要求为零，而普通成员已经有此要求。测试对真实生成的 PAX 修改扩展头填充，再按公开格式重新计算非加密外层校验，使输入确实到达内部解析器。修复前唯一失败记录保存在 `evidence/filesystem-adversarial-pre-fix-results.json`：153 PASS、1 FAIL、1 SKIP；错误用例为 `archive.adversarial.pax.pax-padding-nonzero`。修复后在写入恢复树之前以 `TAR_PADDING` 拒绝。
2. **Junction 显示目标与实际重解析目标未交叉核验。** 原捕获优先采用 PrintName，而恢复实际使用保留的原始重解析数据；两者可能指向不同文本。现由统一解析器读取 SubstituteName，检查数据长度、UTF-16 偏移及边界，恢复预检还要求原始数据解析出的类型和目标与清单一致。测试覆盖目标不一致、原始长度错误、奇数偏移及未知标签；另实际建立并恢复 PrintName 被更改的 Junction，重新捕获仍报告真实 SubstituteName。字段布局按 [Microsoft REPARSE_DATA_BUFFER 文档](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_reparse_data_buffer) 独立实现。

## 审查边界

恢复已拒绝静态父路径重解析点、文件类型冲突和不安全清单路径，并在每个对象创建前复查祖先。但当前接口使用路径 API，不宣称在另一个恶意本地进程同时替换祖先目录时提供完整的基于句柄的路径隔离。恢复应选择当前用户控制的目标目录。整棵目录不是全局回滚事务；单个普通文件通过临时文件验证后替换，先前已经成功恢复的文件可在后续失败时留下。

本模块证据只新增一次独立执行记录，不与稍后的全量 Release 或覆盖率重复运行累计测试数量。报告和最终追踪表应读取统一最终证据后刷新。

## 自主通配符筛选与兼容语义

路径、名称、类型、扩展名及属主规则的通配符由 `filesystem.cpp` 中独立编写的词法解析器和迭代匹配器处理，不调用正则表达式或 Qt 通配符匹配功能。Qt 仅提供字符串容器及 Unicode 单码点大小写折叠；路径安全、摘要文本等其他格式检查仍可使用正则表达式作为基础设施。

- `*` 匹配零个或多个 Unicode 码点，路径中也可跨越 `/`；相邻星号合并。`?` 恰好匹配原输入的一个 Unicode 码点，包括 emoji 等辅助平面字符。
- 普通字符进行不依赖语言环境的 Unicode simple case fold。逐码点折叠保留长度，因此 `ẞ` 与 `ß` 可匹配，但 `SS` 不展开为 `ß`，`İ` 也不会意外使 `?` 消耗两个码点。这是明确的字符匹配语义，不宣称模拟 NTFS 全部版本的排序表。
- `[abc]` 为字符集合，`[a-z]` 为折叠后的闭区间，`[!abc]` 与 `[^abc]` 为取反集合。集合开头的 `]` 以及开头或末尾的 `-` 是字面字符；`[]]` 匹配 `]`，`[[]` 匹配 `[`。反斜杠不充当转义字符，仅路径规则先将 `\` 统一为 `/`；`DOMAIN\user` 属主规则保留原反斜杠。
- 匹配默认覆盖整个候选值。没有通配符的路径规则可匹配该目录及其子树，但要求目录分隔符边界，`source/empty` 不会误命中 `source/empty-other`。
- 未闭合或空的字符集合、反向区间在扫描之前统一以 `FILTER_PATTERN` 拒绝；规则数组中较早的通配命中、或者根目录排除不会掩盖后续规则错误。每条规则最多 32000 个 UTF-16 单元。

匹配器记录最近一个星号位置，失败时迭代尝试多消耗一个码点，无递归和指数级分支树。以规则长度 P、候选长度 T 计，最坏比较次数为 O(P×T)，内存为 O(P+T)。每个匹配另设 8×1024×1024 次显式操作上限，字符集合比较也计入；达到上限以 `FILTER_PATTERN_COMPLEXITY` 报错，不当作不匹配或静默跳过文件。

新增 37 条实际文件筛选用例覆盖上述语法、Unicode、大小写、星号回退、目录边界、错误模式和工作预算。每个正常模式均比较预览的具体文件名集合与实际捕获计数。最终独立模块结果写入 `evidence/filesystem-wildcard-results.json`，未提升系统权限；后续全量统计以统一 Release 证据为准。
